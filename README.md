# Headwaters

An intro animation and crisis-dashboard shell built around where Colorado's rivers actually
begin. Static site, no framework, no runtime dependencies — vanilla JS + one SVG, deployable
on GitHub Pages as-is.

Sibling project to [`headwaters`](https://github.com/mnechromancer/headwaters)
(mnechromancer.github.io/headwaters), which covers the same Colorado water/energy organizing
work in long-form explainer form. This repo is not a replacement for it — different medium
(animated intro + live dashboard vs. static explainers), separate deploy.

Built from `HEADWATERS_INTRO_PLAN.md`, a local planning doc not yet checked into this repo —
ask Jamison for the current copy.

## Site structure

```
index.html                 intro mount point + dashboard mount point + noscript fallback
assets/style.css           tokens on :root, light theme only
assets/intro.js            director + renderer (renderAt(t)) — not yet implemented
assets/dashboard.js        dashboard shell — not yet implemented
data/map.json              generated by scripts/build-map.mjs; committed
data/copy.json             captions + sources; hand-authored
data/status.json           watcher output; may be absent (empty state) — not yet produced
data/events.json           watcher output; may be absent — not yet produced
scripts/build-map.mjs      dev-time only; traces river geometry from USGS NLDI
scripts/rivers.config.json seeds, source citations, terminus rules
tests/                     Playwright
```

## Preview locally

No build step for the site itself — open `index.html` directly, or serve the folder:

```bash
npx serve .
```

To regenerate `data/map.json` from source hydrology data (requires Node 20+):

```bash
npm install
npm run build-map
```

## Before publishing

- **No river geometry is fabricated.** Every headwater coordinate in
  `scripts/rivers.config.json` must carry a real citation (USGS GNIS or NPS/USGS documentation)
  before `map.json` ships.
- **No crypto vocabulary** anywhere in public UI or copy — this project has a verification
  affordance planned for a later pass; it is explicitly out of scope here.
- **Dashboard never shows a value without a source file.** Missing or stale `status.json`/
  `events.json` must render an explicit empty/stale state, never a fabricated number.

## Deploy

Deployed via GitHub Actions (`.github/workflows/pages.yml`) on every push to `main` — see
Settings → Pages for the live URL once the first deploy completes.
